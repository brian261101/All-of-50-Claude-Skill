# Calculation report requirements

File: `<PROJECT>_<TAG>_Design_Calculation_Rev<NN>.pdf` (+ `.html`) in
`01_CALCULATION/`, generated by `python pv_design/pv.py report <package>`.
`report_check.json` re-opens the PDF and confirms the page count and that the
required headings and every calc id are present.

## Sections (numbered as in the PDF)
1 Cover (project, document no., revision, date, code + edition, stage,
input hash, results hash, software, "NOT FOR FABRICATION" banner, status
counts, release blockers) · 2 Project information · 3 Equipment data ·
4 Design code and edition (reference register with verification state) ·
5 Design basis · 6 Material specifications (status, source, table) ·
7 Geometry (components, nozzle schedule) · 8 Input data and units ·
9 Calculation assumptions (global + every record warning) · 10 Calculations by
component · 11 Required thickness · 12 Selected nominal thickness ·
13 Corrosion allowance and mill tolerance · 14 MAWP (all parts) · 15 Nozzle
reinforcement (+ UG-45) · 16 External pressure (+ data required) · 17 Supports
and loads · 18 Test pressure · 19 Weight and volume · 20 Verification results ·
21 Warnings and unresolved items · 22 Material database sources · 23 Revision
history · 24 Engineering review and sign-off (blank boxes).

## Each calculation block
Input → Formula / substitution → Code references (register id, clause,
verification) → Intermediate values → Result → Acceptance criterion, criterion
met, status, status basis, warnings, data required. No calculation is shown as
a bare final number.

## Presentation rules
- Statuses are printed as words. No green anywhere; PASS is plain bold black,
  FAIL red, NEEDS_ENGINEERING_REVIEW amber, NOT_EVALUATED / OUT_OF_SCOPE grey
  italic, computations "COMPUTED". Nothing unevaluated may look accepted.
- The header of every page repeats project, tag, revision and stage; the
  footer repeats "NOT FOR FABRICATION", the results and input hashes, and
  "Page X of N".
- The report must match the package: same input hash and results hash as the
  model, drawings and BOM (`05_QA/consistency.json`).
- Sign-off fields are never filled by software.
